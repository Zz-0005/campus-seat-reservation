# 校园自习座位预约系统

一个可以在本地直接跑起来的自习座位预约系统：按自习室、按日期查看座位，选时段预约、取消预约，
并在多人同时抢同一个座位时保证只有一个人成功。

- 服务端：Python 3 标准库（`http.server` + `sqlite3`），**不需要安装任何第三方包**
- 前端：原生 HTML / CSS / JavaScript 单页，**不需要构建**
- 数据：单个 SQLite 文件，首次启动自动建表并写入演示数据

## 功能对照

| 需求 | 实现方式 |
| --- | --- |
| 切换不同自习室，直观看到座位空闲 / 已预约 | 顶部自习室标签切换 4 间自习室；座位图按行×列排布，绿色为空闲、橙色为部分可约、红色为已约满 |
| 空闲座位可以选择时段预约，预约成功后座位变红 | 点座位 → 右侧列出该座位当天 14 个时段 → 点选起止时段（或"1/2/4 小时"快捷按钮）→ 确认预约，座位立即变红 |
| 已预约座位不能被其他人再次预约 | 已占用时段在界面不可点；即使绕过界面，服务端也会返回 409 |
| 用户可以取消自己未开始的预约，座位变回空闲 | "我的预约"里未开始的预约有"取消预约"按钮；取消后释放时段，座位回到空闲 |
| 个人预约列表正常展示、区分状态 | 列表按"进行中 → 未开始 → 已结束 → 已取消"排序，每条都有状态徽章和"开始前可取消"提示 |
| 多人同时抢同一座位只有一人成功 | 数据库唯一约束 `PRIMARY KEY (seat_id, date, slot)`，冲突时事务回滚并返回 409 |
| 手机也能用（v1.1.0） | 座位图按列均分，375px 宽度下 8 列座位同屏可见、无横向滚动 |
| 页面按 README 说明能本地正常启动 | 见下方"快速开始"，一条命令启动，`python tests/test_booking.py` 可自测 |

## 快速开始

需要 Python 3.9 及以上（Windows / macOS / Linux 均可）。

```bash
# 在项目根目录执行
python server.py
```

Windows 也可以直接双击 `run.bat`。

然后用浏览器打开：

```
http://127.0.0.1:8000
```

首次启动会在 `data/seats.db` 建库，并写入 4 间自习室、146 个座位和几条演示预约。

可选参数：

```bash
python server.py --port 8080          # 换端口（默认 8000）
python server.py --host 0.0.0.0       # 允许局域网访问，方便用手机试
python server.py --db data/other.db   # 换数据库文件
```

停止：在该窗口按 `Ctrl + C`。

### 使用流程

1. 首次打开会要求填写**学号**和**姓名**（本系统是本地演示，不做密码校验，只用来区分预约归属，保存在浏览器本地）。
2. 顶部选择**自习室**和**日期**（可约今天起 7 天）。
3. 点绿色/橙色座位 → 右侧选择时段 → 点"确认预约"。
4. 预约成功后座位变红；"我的预约"里可以看到状态，未开始的可以取消。
5. 页面每 5 秒自动刷新一次，别人刚抢走的座位会自动变红。

### 自测

```bash
python tests/test_booking.py
```

脚本会自己起一个临时数据库的服务端、跑 43 项检查然后关闭，包括 **16 个请求并发抢同一个座位、只允许 1 个成功**。

### 手动验证"多人抢座"

1. 打开两个浏览器窗口（其中一个用无痕模式，避免共用 localStorage）。
2. 两个窗口分别填不同的学号，进入同一间自习室、同一天。
3. 两个窗口都选中同一个座位、同一个时段，几乎同时点"确认预约"。
4. 结果：一个提示"预约成功"，另一个提示"该时段已被他人预约，请换一个时段或座位"，座位变红且只属于一个人。

## 数据模型

| 表 | 说明 |
| --- | --- |
| `rooms` | 自习室：名称、楼栋、楼层、说明、行数、列数 |
| `seats` | 座位：所属自习室、标签（如 `A-01`）、行列位置、类型（靠窗/有电源） |
| `reservations` | 预约主表：用户、座位、日期、起止时段、状态（`confirmed` / `cancelled`） |
| `reservation_slots` | **占用明细**：一行代表"某座位 + 某天 + 某时段"被占用 |

### 为什么并发不会冲突

`reservation_slots` 的主键是 `(seat_id, date, slot)`：

- 一个座位在同一天同一个时段，物理上只能存在一行记录；
- 预约 N 个小时就是在一个事务里插入 N 行，任意一行和已有数据冲突，整个事务回滚；
- 因此并发请求里只有第一个能提交成功，其余会命中唯一约束并拿到 **409**；
- 服务端另外用了一把进程内写锁，避免 SQLite 写锁竞争导致的忙等。

同一时段你也不能同时占两个座位：`reservation_slots` 上还有 `UNIQUE(user_id, date, slot)`。

### 时段规则

- 每天 08:00–22:00，每 1 小时一段，共 14 段；
- 只能预约"开始时间还没到"的时段（当天已开始的时段不可选）；
- 可预约今天起 7 天；
- 预约开始后不能取消（只有"未开始"的预约可以取消）。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meta` | 自习室列表、可选日期、时段配置、服务器时间 |
| GET | `/api/rooms/{roomId}/seats?date=YYYY-MM-DD&userId=...` | 座位图数据：每个座位的占用时段、我的占用、状态 |
| POST | `/api/reservations` | 创建预约，body：`{userId, userName, seatId, date, startSlot, endSlot}` |
| POST | `/api/reservations/{id}/cancel` | 取消预约，body：`{userId}` |
| GET | `/api/reservations?userId=...` | 我的预约列表（含状态与是否可取消） |
| GET | `/api/health` | 健康检查 |

错误返回统一为 `{"error": "人话说明", "code": "SLOT_TAKEN"}`，常见状态码：

- `400` 参数不合法（时段越界、日期过期、时段已开始、非本人操作不允许的状态变更）
- `403` 取消别人的预约
- `404` 座位 / 自习室 / 预约不存在
- `409` 时段已被占用（`SLOT_TAKEN`）或本人同进段已有预约（`USER_OVERLAP`）

## 常见问题

**端口被占用**：换一个端口 `python server.py --port 8080`。

**想重置演示数据**：停掉服务，删除 `data/seats.db`（连同 `seats.db-wal`、`seats.db-shm`），重新启动即可。

**时间不对**：系统按本机时区判断"今天"和"是否已开始"，请确认电脑时间与时区正确。

**换个人身份试试**：点右上角"切换身份"，换一个学号即可（同一个浏览器可以交替使用多个身份）。
