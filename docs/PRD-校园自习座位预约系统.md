# 1. 背景与问题

## 1.1 现状

高校自习座位长期依靠"先到先得"分配：学生到馆后自行找空位，离开时用书本、纸条占座；部分班级或社团用微信群接龙、共享表格登记座位。图书馆与教学楼的座位资源在考试周高度紧张，日常又存在大量空置。

## 1.2 核心痛点

1. **白跑一趟**：学生无法在出发前知道目标自习室还有没有空位，到馆后反复上下楼找座位，时间成本高。
2. **占座无凭证、纠纷无依据**：纸条占座、书本占座没有时间凭证，管理员难以判断谁先谁后，容易引发争执。
3. **登记信息不可信**：微信群接龙和共享表格依赖人工维护，常出现信息过期、重复登记、无法取消等问题。
4. **管理侧缺少实时数据**：管理员无法掌握每个自习室当前的实际占用率，无法据此做引导或限流。
5. **同一时段被重复预约**：多人同时抢同一个座位时，人工登记无法保证唯一性，容易出现"两个人都以为自己约到了"的情况。

## 1.3 现有方案对比

| 方案 | 优点 | 主要不足 |
| --- | --- | --- |
| 现场先到先得 | 零成本、无需学习 | 无法提前规划，找座耗时，占座纠纷多 |
| 微信群接龙 / 共享表格 | 零成本、上手快 | 依赖人工维护，信息易过期，并发下无法保证唯一 |
| 商业座位预约小程序 | 体验完善、有提醒 | 需要接入第三方、涉及账号与隐私授权，无法离线使用 |
| 本系统 | 可本地部署、零第三方依赖、并发下保证唯一、状态实时可见 | 面向单机小规模场景，暂不做真实登录与违约惩罚 |

## 1.4 为什么现在做

第一版定位为**可独立运行、可离线部署、零第三方依赖**的课程演示系统：只用一个 Python 进程和一个 SQLite 文件即可运行，不依赖云服务、不收集敏感个人信息，同时把"并发下座位唯一"这个最容易出错的技术点做扎实。

# 2. 产品目标与非目标

## 2.1 产品目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G-01 | 让学生出发前就能判断"有没有座、哪个座、哪个时段" | 打开页面 1 步内可见当前自习室全部座位的空闲/占用状态 |
| G-02 | 用明确的时段预约取代纸条占座，产生可追溯的占用凭证 | 每条预约都有预约人、座位、日期、起止时段、状态 |
| G-03 | 彻底消除"同一座位同一时段被两人预约"的情况 | 并发测试中同一座位同一时段仅允许 1 条占用记录 |
| G-04 | 支持自助取消，让空出来的座位立即回到可约状态 | 取消后对应时段即时恢复为空闲，可被他人预约 |
| G-05 | 一套代码可在任意一台电脑本地跑起来，便于课程演示 | 一条命令启动，无需安装第三方包，无需联网 |

## 2.2 非目标（第一版明确不做）

1. 不做真实身份认证：不接入校园统一认证，不校验学号真实性，不设密码。
2. 不做管理员后台：不做自习室管理、座位增删、批量导入、占用率报表。
3. 不做违约惩罚：不记录爽约、不做信用分、不做黑名单。
4. 不做提醒通知：不接短信、邮件、微信模板消息。
5. 不做多校区 / 多租户：单实例、单学校场景。
6. 不做高并发互联网部署：目标是数十人同时在线的局域网或单机场景。

## 2.3 成功标准

第一版通过验收的最低标准：第 10 章列出的全部验收用例通过；其中"16 个请求同时抢同一座位同一时段，只有 1 个成功"必须成立。

# 3. 用户与使用场景

## 3.1 用户角色

| 角色 | 描述 | 使用目标 | 本版是否覆盖 |
| --- | --- | --- | --- |
| 学生（主要用户） | 需要使用自习座位的在校学生 | 快速找到并预约空闲座位，必要时取消 | 是 |
| 自习室管理员 | 负责自习室秩序与资源调配 | 了解占用情况、处理占座纠纷 | 否（第一版不做后台） |
| 课程评审 / 演示者 | 需要短时间验证系统能力 | 快速跑起系统、验证并发与状态流转 | 是 |

## 3.2 典型场景

**场景一：出发前确认有没有座。** 小李晚上七点想去图书馆自习。他打开系统，切到"图书馆 A 区自习室"，看到上午满格的座位图现在有 20 多个绿色座位，选中一个靠窗座位，预约了 19:00–21:00，然后出门。

**场景二：考试周抢座。** 张同学和王同学都想约同一个热门座位 14:00–16:00。两人几乎同时点下"确认预约"：张同学看到"预约成功"，王同学看到"该时段已被他人预约，请换一个时段或座位"，座位图随即变红。两人都不会对"到底约到没约到"产生歧义。

**场景三：计划变更后释放座位。** 小王上午约了下午三点的座位，临时有事。他在"我的预约"里找到这条未开始的预约，点"取消预约"，确认后座位立刻回到空闲，可以被别人预约；已取消的记录仍然保留在列表里，状态显示"已取消"。

# 5. 功能需求详述

## 5.1 FR-01 自习室切换与座位图展示

**描述**：页面顶部提供自习室标签，切换后展示该自习室的座位图；座位图按"行 × 列"真实排布，每个座位显示编号（如 A-01）与属性（靠窗 / 有电源）。

**业务规则**

1. 系统内预置 4 间自习室：图书馆 3 层 A 区（48 座，静音）、图书馆 3 层 B 区（48 座，可讨论）、第一教学楼 A201（30 座）、东区宿舍 1 号楼共享自习室（20 座），合计 146 个座位。
2. 座位编号规则为"行字母 + 列号"，如 A-01 表示第一行第一列。
3. 座位颜色由该座位在**所选日期**内的可约时段数量决定，规则见 6.3。
4. 切换自习室时，未提交的时段选择被清空，避免误约到另一间自习室。

**验收标准**

- AC-01：进入页面默认展示第一间自习室的座位图，座位数量与该自习室配座位数一致。
- AC-02：点击任一自习室标签，座位图、标题、座位数、统计提示同步更新。
- AC-03：座位图列数与自习室实际列数一致（如 8 列自习室显示 8 列）。

## 5.2 FR-02 日期选择

**描述**：页面提供日期切换条，可查看今天及未来 6 天的座位状态。

**业务规则**

1. 可选日期范围为今天起 7 天（含今天），超出范围不可选。
2. 当天已开始的时段视为不可约，界面上置灰且不可点击。
3. 当天已闭馆（22:00 之后）时，该日全部时段不可约，座位统一显示为"不可约"。

**验收标准**

- AC-04：日期条展示 7 天，今天带"今天"标识。
- AC-05：切换日期后，座位颜色与可约时段随之刷新。

## 5.3 FR-03 时段选择与创建预约

**描述**：点击座位后，右侧面板列出该座位所选日期的全部时段（08:00–22:00，每小时一段，共 14 段），用户选择一段连续区间后提交预约。

**业务规则**

1. 时段固定为 08:00 起、22:00 止，每段 1 小时，共 14 段。
2. 只能选择**连续**且**全部空闲**的时段区间；区间内包含被占用或已开始的时段时，选择会被重置。
3. 提供"1 小时 / 2 小时 / 4 小时"快捷选择，从当前可约的第一个时段起算。
4. 提交时必须携带：学号、姓名、座位、日期、开始时段、结束时段。
5. 同一用户在同一日期同一时段只能占用一个座位。

**验收标准**

- AC-06：选择合法区间后"确认预约"按钮可点击；未选时段时按钮禁用。
- AC-07：预约成功后提示成功，座位图立即变红，"我的预约"出现该条记录。
- AC-08：同一用户在同一天同一时段预约第二个座位时，请求被拒绝并提示"你在该时段已经有其他座位的预约"。
- AC-09：选择已开始的时段提交，服务端拒绝并提示"该时段已开始，请选择更晚的时段"。

## 5.4 FR-04 预约冲突控制（并发唯一）

**描述**：在任意并发情况下，同一座位同一日期同一时段最多只有一条有效占用记录，其余请求必须被明确拒绝。

**业务规则**

1. 占用以"座位 + 日期 + 时段"为最小单位落库，该组合在数据库中唯一。
2. 一次预约 N 小时即在同一个事务中写入 N 行占用记录；任意一行冲突，整个事务回滚，不产生半条预约。
3. 冲突时返回 HTTP 409，并区分两类原因：座位已被他人占用（`SLOT_TAKEN`）、本人该时段已有其他预约（`USER_OVERLAP`）。
4. 冲突判断以数据库约束为准，不以页面按钮状态为准；即使绕过界面直接调用接口，也不会产生重复占用。
5. 已取消的预约不再占用时段，其占用记录同时删除。

**验收标准**

- AC-10：16 个请求同时抢同一座位同一时段，恰好 1 个成功（HTTP 201），其余 15 个返回 409。
- AC-11：并发结束后，数据库中该座位该时段只有一条占用记录。
- AC-12：部分冲突的请求（如 11:00–13:00 与已有 12:00–13:00 冲突）整笔失败，不留下 11:00–12:00 的占用。

## 5.5 FR-05 取消预约

**描述**：用户可以取消自己尚未开始的预约，取消后座位对应时段立即恢复空闲。

**业务规则**

1. 仅预约本人可取消，他人取消返回 403。
2. 仅"未开始"的预约可取消；已开始（进行中）或已结束的预约不可取消。
3. 取消为软状态变更：预约记录保留并标记为"已取消"，同时删除其占用记录以释放时段。
4. 重复取消返回 400（已取消）。
5. 取消后，被释放的时段可以被本人或他人重新预约。

**验收标准**

- AC-13：取消未开始预约后，座位图对应时段恢复绿色，"我的预约"状态变为"已取消"。
- AC-14：取消他人预约返回 403，且原预约保持不变。
- AC-15：重复取消同一预约返回 400。
- AC-16：取消释放的时段，其他用户可预约成功。

## 5.6 FR-06 个人预约列表与状态区分

**描述**：右侧"我的预约"按状态展示当前身份的全部预约记录。

**业务规则**

1. 状态定义：未开始（当前时间早于开始时间）、进行中（处于时段内）、已结束（已过结束时间）、已取消。
2. 排序：进行中 → 未开始 → 已结束 → 已取消，同状态内按日期、开始时段升序。
3. 每条记录展示座位编号、自习室名称、日期、时段、状态标签；未开始的记录额外展示"取消预约"按钮。
4. 列表不做分页，最多展示该用户的全部记录。

**验收标准**

- AC-17：列表能同时出现不同状态的记录，且状态文案与颜色可区分。
- AC-18：只有"未开始"的记录带取消按钮；已结束、已取消的记录没有取消按钮。

## 5.7 FR-07 用户身份标识

**描述**：首次进入时填写学号与姓名，作为预约归属的标识，保存在浏览器本地。

**业务规则**

1. 学号为 3–20 位字母、数字、下划线或连字符；姓名为 1–20 个字符，均为必填。
2. 身份保存在浏览器 localStorage，刷新页面不丢失；可随时通过右上角"切换身份"更换。
3. 身份不参与鉴权，仅用于区分预约归属（见 2.2 非目标）。

**验收标准**

- AC-19：未填写身份时弹出身份框，填写非法学号时给出格式提示并不放行。
- AC-20：填写后刷新页面，身份仍在；切换身份后"我的预约"切换为对应身份的记录。

## 5.8 FR-08 状态自动刷新

**描述**：页面每 5 秒静默同步一次座位图与个人预约，保证多人同时使用时状态及时可见。

**业务规则**

1. 刷新失败不打断当前操作，仅以轻提示告知。
2. 刷新时若用户当前选中的时段已被他人占用，则清空选择并提示重新选择。
3. 页面从后台切回前台时立即刷新一次。
4. 页面不可见（切换标签页、最小化窗口）时暂停轮询，不产生任何请求；回到前台先刷新一次再恢复轮询。

**验收标准**

- AC-21：另一浏览器窗口完成预约后，本窗口 5 秒内自动变红。
- AC-22：所选时段在刷新时被抢占后，选择被重置，"确认预约"按钮回到禁用状态。
- AC-23：页面置于后台 10 分钟期间服务端无新增请求；切回前台后 2 秒内完成一次刷新。

## 6.1 信息架构

```
    ├── 左侧：座位图（宫格，含讲台/入口标识与图例）
    └── 右侧
        ├── 座位预约面板（时段列表、快捷时长、确认预约）
        └── 我的预约（状态标签、取消入口）
```

## 6.2 页面清单

| 页面 / 区域 | 内容 | 关键操作 |
| --- | --- | --- |
| 身份弹窗 | 学号、姓名输入与格式提示 | 进入系统、修改身份 |
| 座位图区域 | 座位宫格、图例、统计提示 | 切换自习室、切换日期、点击座位 |
| 预约面板 | 已选时段摘要、时段列表、快捷时长、确认预约 | 选择起止时段、快捷选 1/2/4 小时、清空、提交 |
| 我的预约 | 预约卡片（座位、自习室、日期、时段、状态） | 取消未开始的预约 |

## 6.3 座位状态定义

| 状态 | 视觉 | 判定规则 | 可点击 |
| --- | --- | --- | --- |
| 空闲 | 绿色 | 该日期全部可约时段均未占用 | 是 |
| 部分可约 | 橙色 | 该日期仍有可约时段，但部分已被占用 | 是 |
| 已约满 | 红色 | 该日期全部可约时段均被占用 | 否 |
| 不可约 | 灰色 | 该日期已无可约时段（当天已闭馆或时段已过） | 否 |
| 我的预约 | 绿色/橙色 + 蓝色描边与"我"标签 | 该日期存在本人的占用 | 是 |

**窄屏（宽度 ≤ 560 px）展示规则**：座位按列均分占满容器宽度，仅保留座位编号、隐藏"靠窗/电源"等备注，行列间距与字号同步收缩，保证不出现横向滚动。

## 6.4 时段状态定义

| 状态 | 视觉 | 说明 | 可点击 |
| --- | --- | --- | --- |
| 可预约 | 白色 | 该时段空闲且尚未开始 | 是 |
| 已选 | 浅蓝 | 处于当前选择区间内 | 是（用于调整区间） |
| 已被预约 | 浅红 | 已被他人占用 | 否 |
| 我的预约 | 浅蓝 | 已被本人占用 | 否 |
| 已过时段 | 灰色 | 该时段已经开始或整日已闭馆 | 否 |

## 6.5 关键流程

**预约流程**：填写身份 → 选择自习室 → 选择日期 → 点击座位 → 选择连续时段 → 点"确认预约" → 成功则提示并刷新，失败则提示原因并刷新座位图。

**取消流程**：打开"我的预约" → 找到状态为"未开始"的记录 → 点"取消预约" → 二次确认 → 提示取消成功 → 座位图与列表刷新。

**冲突流程**：两人同时提交 → 数据库唯一约束决定先后 → 一方收到"预约成功"，一方收到"该时段已被他人预约，请换一个时段或座位" → 双方座位图均在 5 秒内刷新为最新状态。

## 6.6 空态与异常态

| 场景 | 表现 |
| --- | --- |
| 无任何预约 | "我的预约"显示"还没有预约，选一个座位开始吧" |
| 座位当天全部约满 | 座位显示红色且不可点击，悬停提示"该座位当天剩余时段已全部预约" |
| 当天已闭馆 | 全部座位显示灰色，提示"当天已无可约时段" |
| 服务端不可达 | 顶部轻提示"无法连接服务器"，页面保留上次数据 |
| 提交时被抢占 | 轻提示冲突原因，并自动清空已选时段 |

# 7. 数据模型

## 7.1 实体关系

- 一个自习室（rooms）包含多个座位（seats）；
- 一个座位（seats）可以被多条预约（reservations）占用，但同一天同一时段只能有一条；
- 一条预约（reservations）按小时拆分为多条占用明细（reservation_slots），占用明细是唯一性约束的载体。

## 7.2 表结构

**rooms（自习室）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | 自习室 ID |
| name | TEXT | 名称，如"A 区自习室 · 静音" |
| building | TEXT | 楼栋 |
| floor | INTEGER | 楼层 |
| description | TEXT | 说明（静音/可讨论/位置特点） |
| rows / cols | INTEGER | 座位排布行数、列数 |
| sort_order | INTEGER | 展示顺序 |

**seats（座位）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | 座位 ID |
| room_id | INTEGER FK | 所属自习室 |
| label | TEXT | 座位编号，如 A-01（同一自习室内唯一） |
| row / col | INTEGER | 行、列位置 |
| kind | TEXT | 属性：window（靠窗）/ power（有电源）/ normal |

**reservations（预约主表）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | 预约 ID（32 位十六进制） |
| user_id | TEXT | 学号 |
| user_name | TEXT | 姓名 |
| seat_id | INTEGER FK | 座位 |
| date | TEXT | 预约日期（YYYY-MM-DD） |
| start_slot / end_slot | INTEGER | 开始时段、结束时段（不含 end_slot） |
| status | TEXT | confirmed（生效）/ cancelled（已取消） |
| created_at / cancelled_at | TEXT | 创建时间、取消时间 |

**reservation_slots（占用明细，唯一性载体）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| seat_id | INTEGER | 座位 |
| date | TEXT | 日期 |
| slot | INTEGER | 时段序号（0–13） |
| reservation_id | TEXT FK | 对应预约 |
| user_id | TEXT | 占用者学号 |
| 主键 | (seat_id, date, slot) | 保证同一座位同一时段唯一占用 |
| 唯一索引 | (user_id, date, slot) | 保证同一人同一时段只占一个座位 |

# 8. 接口设计

## 8.1 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meta` | 自习室列表、可选日期、时段配置、服务器时间 |
| GET | `/api/rooms/{roomId}/seats?date=&userId=` | 座位图数据：每个座位的占用时段、本人占用、状态 |
| POST | `/api/reservations` | 创建预约 |
| POST | `/api/reservations/{id}/cancel` | 取消预约 |
| GET | `/api/reservations?userId=` | 个人预约列表（含状态、是否可取消） |
| GET | `/api/health` | 健康检查 |

## 8.2 创建预约示例

请求：

```json
{
  "userId": "2024001",
  "userName": "李明",
  "seatId": 5,
  "date": "2026-10-25",
  "startSlot": 5,
  "endSlot": 7
}
```

成功响应（HTTP 201）：

```json
{
  "reservation": {
    "id": "0f3c...b1",
    "seatLabel": "A-05",
    "roomName": "A 区自习室 · 静音",
    "date": "2026-10-25",
    "startSlot": 5,
    "endSlot": 7,
    "timeRange": "13:00 - 15:00",
    "status": "upcoming",
    "cancellable": true
  }
}
```

冲突响应（HTTP 409）：

```json
{
  "error": "该时段已被他人预约，请换一个时段或座位",
  "code": "SLOT_TAKEN",
  "conflicts": [6]
}
```

## 8.3 错误码约定

| HTTP | code | 触发条件 | 前端表现 |
| --- | --- | --- | --- |
| 400 | BAD_USER / BAD_DATE / BAD_SLOT | 学号、日期、时段参数不合法 | 提示具体原因，不给提交 |
| 400 | SLOT_STARTED | 预约时段已经开始 | 提示"该时段已开始，请选择更晚的时段" |
| 400 | DAY_CLOSED | 当天已闭馆 | 提示"当天已闭馆，无法预约" |
| 400 | ALREADY_CANCELLED | 重复取消 | 提示"该预约已取消" |
| 400 | ALREADY_STARTED | 取消已开始的预约 | 提示"预约已开始或已结束，无法取消" |
| 403 | NOT_OWNER | 取消他人预约 | 提示"只能取消自己的预约" |
| 404 | SEAT_NOT_FOUND / ROOM_NOT_FOUND / RESERVATION_NOT_FOUND | 对象不存在 | 提示对象不存在并刷新 |
| 409 | SLOT_TAKEN | 座位时段已被占用 | 提示"该时段已被他人预约"并刷新座位图 |
| 409 | USER_OVERLAP | 本人该时段已有其他预约 | 提示"你在该时段已经有其他座位的预约" |
| 500 | INTERNAL | 未预期错误 | 提示"服务器内部错误"，可重试 |

# 9. 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 并发正确性 | 同一座位同一时段的并发预约，成功数必须恰好为 1；约束由数据库保证，不依赖前端 |
| NFR-02 | 性能 | 单座位图请求（48 座、14 时段）在本机响应时间低于 100 ms；页面首屏可交互时间低于 1 s |
| NFR-03 | 容量 | 支持 4 间自习室、约 150 座位、每天数百条预约；单机数十人同时在线 |
| NFR-04 | 依赖 | 仅依赖 Python 3.9+ 标准库，无需安装第三方包、无需联网、无需外部数据库 |
| NFR-05 | 兼容性 | 支持 Chrome / Edge / Firefox 等现代浏览器，窗口宽度 1080 px 以下自动单列布局 |
| NFR-06 | 数据持久化 | 数据存于单个 SQLite 文件；删除该文件即可重置为初始演示数据 |
| NFR-07 | 可维护性 | 前后端分离清晰：`server.py` 只提供 JSON 接口，`static/` 为纯静态资源；接口与错误码有文档 |
| NFR-08 | 时间正确性 | 以服务器本机时区判断"今天"和"是否已开始"，跨日、闭馆等边界均有明确规则 |
| NFR-09 | 隐私 | 仅收集学号与姓名，且只保存在用户浏览器本地与服务端预约记录中，不外传 |
| NFR-10 | 移动端适配 | 375 px 宽度下页面无横向滚动，8 列自习室的全部座位同屏可见；触控目标不小于 32 px |
| NFR-11 | 日志可读性 | 客户端断开连接只记录一行提示，不打印堆栈；正常请求与错误响应的日志可区分，便于定位真实故障 |

# 12. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
| --- | --- | --- | --- |
| 前端状态与后端不一致导致"看到空闲但约不上" | 用户困惑 | 中 | 冲突一律以服务端判定为准并提示原因；页面 5 秒自动刷新 |
| 并发下重复预约 | 座位纠纷、数据错误 | 低（已治理） | 数据库唯一约束 + 事务回滚；并发用例覆盖 |
| 身份可被冒用（无鉴权） | 他人用你的学号预约 | 高（设计取舍） | 明确列为非目标；后续版本接入校园统一认证 |
| 用户爽约导致座位浪费 | 资源利用率下降 | 高 | 后续版本加入签到与违约惩罚 |
| 演示数据被误删 | 演示受阻 | 低 | 删除数据库文件即自动重建演示数据，README 已说明 |
| 单机 SQLite 写并发瓶颈 | 高峰期提交变慢 | 低 | 单机小规模场景足够；后续可换 PostgreSQL |
| 时区或系统时间不准 | "今天""是否已开始"判断错误 | 低 | 统一以服务器本机时间为准，README 提示校时 |

# 13. 附录

## 13.1 术语

| 术语 | 说明 |
| --- | --- |
| 时段（slot） | 最小预约单位，固定 1 小时，全天 14 段（08:00–22:00） |
| 占用明细 | 座位 + 日期 + 时段 的一条记录，是唯一性约束的载体 |
| 未开始 / 进行中 / 已结束 / 已取消 | 预约的四种状态，由当前时间与预约时段计算得出 |
| 部分可约 | 座位当天仍有空闲时段，但部分时段已被占用 |
